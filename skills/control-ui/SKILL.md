# Control UI

Use local browser automation to verify UI behavior with concrete evidence. Reuse the repository's own Playwright, Cypress, or Electron harness first. When none exists, assemble a temporary local harness around an isolated dev server and Chromium debug session.

## When to Use It

- Reproducing UI bugs that depend on real browser focus, keyboard input, scrolling, resizing, or rendering.
- Verifying visual parity or accessibility changes with screenshots and ARIA snapshots inside `/pstack` (`build` and `diagnose` topologies).
- Driving adversarial UI repros in `/interrogate` (`adv-*`) or independent live checks in `ro-verify`.
- Capturing console errors, network logs, CPU profiles, traces, or heap snapshots.
- Supplying the browser harness layer for project-local skills generated by [`/verify-gen`](../verify-gen/SKILL.md).

## Swarm Worker Isolation

Parallel swarm workers (`impl-*`, `cand-*`, `adv-*`, and `ro-verify`) share one machine and collide immediately if they bind default ports or reuse browser profiles. Enforce four isolation rules on every run.

1. **Ephemeral app ports.** Start dev servers and local APIs on OS-assigned or worker-unique ports (`--port 0` or an explicit free port) and parse the bound URL from startup output instead of assuming `3000`, `4173`, or `5173`.
2. **Isolated `--user-data-dir` and CDP port.** Launch every Chromium or Electron instance with `--user-data-dir=/tmp/ui-profile-<worker>-<run>` and `--remote-debugging-port=0` (reading `DevToolsActivePort` in that profile directory or the `ws://127.0.0.1:<port>` stderr line). Concurrent workers never share cookies, IndexedDB, service workers, or debug sockets.
3. **Scoped `/tmp` artifact directories.** Write screenshots, ARIA snapshots, traces, and temporary probe scripts to `/tmp/ui-artifacts-<worker>-<run>/`. Hook guards block `ro-*` workers from writing inside the repository tree, so `/tmp` keeps probes portable across all roles.
4. **Exact PID teardown.** Record the exact PIDs of dev servers and browser instances started by this worker and kill only those PIDs on exit, then remove the disposable profile directory while retaining proof artifacts needed for `#seq` board reports.

## Setup Pattern

1. Discover existing local harnesses such as Playwright tests, Cypress specs, Storybook runners, Electron launch scripts, or snapshot helpers.
2. Start the app locally with the repository's documented dev command, overriding port and data-directory flags for worker isolation.
3. Connect to the bound local URL with existing browser tooling, or launch Chromium or Electron with an isolated `--user-data-dir` and remote debugging port.
4. Select the target page by stable app markers rather than tab index.
5. Prefer accessibility roles, accessible names, and stable `data-*` attributes over CSS paths or screen coordinates.

## Generic Web Harness

Reuse installed browser dependencies when present. Do not add Playwright to `package.json` just for a one-off probe unless the user asks.

```javascript
import { chromium } from "playwright";

const runDir = `/tmp/ui-artifacts-${process.env.WORKER_NAME ?? "local"}-${Date.now()}`;
const context = await chromium.launchPersistentContext(`${runDir}/profile`, {
  headless: true,
  viewport: { width: 1280, height: 800 },
});
const page = context.pages()[0] ?? (await context.newPage());
await page.goto(process.env.APP_URL);
await page.getByRole("button", { name: /submit/i }).click();
await page.screenshot({ path: `${runDir}/after.png`, fullPage: true });
await context.close();
```

## Generic CDP Harness

For Electron or Chromium launched with `--user-data-dir=<profile-dir>` and `--remote-debugging-port=<debug-port>`, connect over CDP and match a positive page marker.

```javascript
import { chromium } from "playwright";

const browser = await chromium.connectOverCDP(`http://127.0.0.1:${process.env.CDP_PORT}`);
const pages = browser.contexts().flatMap((ctx) => ctx.pages());
let page;
for (const candidate of pages) {
  if (await candidate.locator("<app-root-selector>").count()) {
    page = candidate;
    break;
  }
}

if (!page) {
  const openPages = await Promise.all(
    pages.map(async (p) => ({ title: await p.title(), url: p.url() }))
  );
  console.log(openPages);
  throw new Error("No matching app page found");
}

await page.screenshot({ path: "/tmp/ui-artifacts-cdp.png", fullPage: true });
await browser.close();
```

Replace `<app-root-selector>` with a stable landmark or `data-*` root from the current repository.

## Interaction Loop

1. Capture an ARIA snapshot or screenshot before acting.
2. Pick one target handle from the current page structure.
3. Execute a single structural action (click, fill, keypress, drag, scroll, navigate, or resize).
4. Wait on an observable DOM or network state transition rather than a fixed sleep.
5. Capture a fresh snapshot or screenshot and verify the expected state change.
6. Record before-and-after artifact paths when reporting `#seq` proof on the swarm board.

## Raw CDP Capabilities

Drop down to raw CDP sessions (`context.newCDPSession(page)`) only when standard browser APIs cannot observe the signal.

- **Performance.** CPU profiles, trace events, paint flashing, frame-rate meters, and layout-shift attribution.
- **Memory.** Forced garbage collection and before-and-after heap snapshots for leak diagnosis.
- **Network.** Request interception, offline or latency emulation, cache disablement, and payload capture.
- **Rendering.** Media-query emulation (`prefers-color-scheme`, `prefers-reduced-motion`), DPR scaling, and accessibility tree dumps.
- **Runtime.** Console stream capture, uncaught exception hooks, and computed style queries.

## Page Selection

When an Electron or IDE instance opens background workers, devtools windows, or splash screens alongside the main window, follow three rules.

- Match a positive marker unique to the surface under test, such as a root landmark or product `data-*` attribute.
- Exclude devtools or hidden background targets with a negative URL or selector filter when needed.
- Dump all candidate `{ title, url }` pairs and fail loudly instead of guessing when zero pages match.

## Guardrails

- Re-query locators after navigation or re-render instead of holding stale element handles.
- Avoid coordinate clicks unless canvas rendering leaves no DOM handle and a fresh screenshot was just captured.
- Keep test fixtures local and disposable.
- Never capture or retain screenshots or heap snapshots from privacy-sensitive user profiles unless explicitly authorized.
- Never hard-code selectors, ports, or paths from another repository.
- Tear down worker-owned dev servers, debug browsers, and temporary profile directories before ending the turn.
